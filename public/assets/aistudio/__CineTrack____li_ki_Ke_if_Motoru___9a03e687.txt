## 1. Asıl hata: Halka, gösterim geçmişine göre değil puana göre atanıyor

`src/core/cinetrack-core.ts` içindeki `assignTasteRing` fonksiyonu hâlâ eski dört halkalı puan sistemini kullanıyor:

```
export function assignTasteRing(score: number, context?: {
  inLastBatch?: boolean;
  shownCount?: number;
  skippedCount?: number;
}): TasteRing {
  if (context?.inLastBatch) return 'ring1';
  if ((context?.skippedCount || 0) > 0 ||
      (context?.shownCount || 0) > 0) return 'ring2';
  if (context !== undefined) return 'ring0';

  const s = Number(score) || 0;
  if (s >= 85) return 'core';
  if (s >= 70) return 'inner';
  if (s >= 55) return 'outer';
  return 'orbit';
}
```

Sorun şu: puanlama sırasında daha önce kaydı bulunmayan adaylar için de bu fonksiyon yalnızca puanla çağrılıyor. Ardından `updateTasteMapWithBatch`, `normalizeLegacyRings: true` ile eski isimleri yeni halkalara çeviriyor. Eski eşlemeler `core → ring0`, `inner → ring1`, `outer/orbit → ring2`.&#x20;

Bunun sonucu şöyle:

| Adayın puanı | Eski halka | Normalleştirme sonrası | Mevcut sistemdeki anlam  |
| ------------ | ---------- | ---------------------- | ------------------------ |
| 85–100       | `core`     | `ring0`                | Yeni eşleşme             |
| 70–84        | `inner`    | `ring1`                | Yakın zamanda gösterildi |
| 55–69        | `outer`    | `ring2`                | Daha önce atlandı        |
| 0–54         | `orbit`    | `ring2`                | Daha önce atlandı        |

Yani daha önce hiç önerilmemiş, 75 puanlı bir film bile `ring1` olarak kaydedilebiliyor. Benzer biçimde, 60 puanlı yeni bir film hiç gösterilmemiş olmasına rağmen `ring2` yapılabiliyor.

Bu ciddi bir mantık hatası; çünkü yeni sistemde halkaların puanı değil, içeriğin gösterim geçmişini ifade etmesi gerekiyor.

## 2. Bu hata, eski önerilerin neden tekrar geldiğini açıklıyor

İkinci sorun `selectBalancedRecommendations` içinde. Seçici önce `ring0` adaylarını kullanıyor; bunlarla hedef sayı doldurulamazsa `ring2` adaylarını devreye alıyor. Yakın zamanda gösterilen `ring1` adayları dışarıda bırakılıyor.&#x20;

Halkalar puana göre yanlış atanırsa gerçek yeni adayların önemli bir kısmı `ring1` veya `ring2` oluyor. Böylece yeni adaylardan oluşan `ring0` havuzu yapay biçimde küçülüyor. Seçici 20 öneriyi tamamlamak için `ring2` adaylarına geçiyor ve bunların arasında daha önce gösterilmiş, ancak kullanıcı tarafından hiçbir listeye eklenmemiş filmler de bulunabiliyor.

## 3. Nasıl düzeltmeliyiz?

Bence üç düzeltme birlikte yapılmalı. Yalnızca `ring2` cezasını düzeltmek yeterli olmaz; yanlış atanmış halka kayıtları depoda kalmaya devam eder.

### Düzeltme A — Halka ataması puandan bağımsız olmalı

Yeni semantik şöyle olmalı:

- `ring0`: Daha önce hiç gösterilmemiş aday.
- `ring1`: En son öneri grubunda gösterilmiş aday; sonraki listeden çıkarılır.
- `ring2`: Daha önce gösterilmiş fakat kaydedilmemiş aday; yeni adaylar yeterliyse gösterilmez, uygun yeni aday kalmadığında yedek olarak değerlendirilebilir.

Halka seçimi için yeni bir yardımcı fonksiyon eklenebilir:

```
type LifecycleRing = 'ring0' | 'ring1' | 'ring2';

function inferLifecycleRing(
  mediaKey: string,
  entry: {
    shownCount?: number;
    skippedCount?: number;
    lastShownAt?: string | null;
  } | undefined,
  lastRecommendedKeys: string[]
): LifecycleRing {
  if (lastRecommendedKeys.includes(mediaKey)) {
    return 'ring1';
  }

  const hasBeenShown =
    (entry?.shownCount ?? 0) > 0 ||
    (entry?.skippedCount ?? 0) > 0 ||
    Boolean(entry?.lastShownAt);

  return hasBeenShown ? 'ring2' : 'ring0';
}
```

Bu fonksiyonun amacı, bir içeriği puanına göre değil gerçek gösterim geçmişine göre sınıflandırmak. İlk kez karşılaşılan bir aday 60, 75 veya 95 puan alması fark etmeksizin `ring0` olur.

Eski `core`, `inner`, `outer`, `orbit` kayıtlarının dönüşümü de yalnızca `normalizeTasteRing` ile yapılmamalı. Bu eski değerler puan seviyelerini temsil ettiği için doğrudan yeni yaşam döngüsü halkasına çevrilemez. `loadPersistentTasteMap` sırasında kayıtlar `shownCount`, `skippedCount`, `lastShownAt` ve `lastRecommendedKeys` üzerinden bir kez yeniden sınıflandırılmalı.

### Düzeltme B — Geriletme cezası yeni halka değerlerinde de korunmalı

`scoreCandidatesV3` içinde `ring2` durumunda `demotionPenalty` sıfırlanmamalı. Mevcut kayıt üzerinden alınmalı:

```
const inLastBatch = Boolean(
  tasteMap?.lastRecommendedKeys?.includes(key)
);

const ring = inferLifecycleRing(
  key,
  tasteEntry,
  tasteMap?.lastRecommendedKeys ?? []
);

const demotionPenalty = inLastBatch
  ? 0
  : Math.max(0, Number(tasteEntry?.demotionPenalty) || 0);

const tasteScore = Math.max(
  1,
  Math.min(100, Math.round(rawScore))
);

const priorityScore = Math.max(
  1,
  Math.min(100, Math.round(tasteScore - demotionPenalty))
);
```

Buradaki `key`, aday için `makeMediaKey(candidate)` ile oluşturulmalı. Bu kod mevcut `scoreCandidatesV3` içine uyarlanmalı; doğrudan bütün fonksiyonun yerine kopyalanmamalı.

Böylece iki puan arasındaki ayrım korunur:

- `tasteScore`: İçeriğin kullanıcının zevk profiline gerçek uyumu.
- `priorityScore`: Gösterim geçmişi ve geriletme nedeniyle öneri listesindeki önceliği.

### Düzeltme C — Her gösterim atlanınca bir sonraki liste için doğru durum kaydedilmeli

Önceki listedeki bir içerik yeni listeye seçilmediyse ve kullanıcı onu kaydetmediyse `skippedCount` artırılmalı ve `ring2` olarak işaretlenmeli. Mevcut kodda bulunan “iki atlamada bir halka düşür” koşulu bu davranışla uyumlu olacak şekilde değiştirilmelidir.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

Seçici tarafında da şu kural kesin olarak uygulanmalı:

1. Önce `ring0` adaylarından seç.
2. `ring1` adaylarını her durumda dışarıda tut.
3. Ancak yeterince uygun `ring0` adayı kalmadıysa `ring2` adaylarına geç.
4. `ring2` adaylarını kendi `priorityScore` değerine göre sırala; kalan havuzdan seçim yapan son aşama bu halkaları birbirine karıştırmamalı.

Bu, `selectBalancedRecommendations` içinde özellikle `remainingMovies` ve `remainingTv` üzerinden yapılan son tamamlama geçişine de uygulanmalı. Mevcut son geçiş, `ring1` dışındaki bütün adayları yeniden değerlendirebiliyor; `ring2` önceliğini açık biçimde korumuyor.&#x20;

## 4. Düzeltmenin çalıştığını nasıl anlayacağız?

Mevcut testler `skippedCount` ve geriletme cezasını kontrol ediyor; ancak bir içerik önerildiğinde, kaydedilmediğinde ve sonraki birkaç güncellemede yeniden seçilip seçilmediğini gerçek sıralama/seçim zinciriyle sınayan kapsam yetersiz. Bazı testlerde hâlâ `core → inner` gibi eski halka değerlerinin beklendiği görülüyor.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub

+1



Şu testleri eklemeliyiz:

- İlk defa karşılaşılan, 60 puanlı ve 75 puanlı adaylar `ring0` olmalı.
- Son öneri grubundaki içerikler bir sonraki grubun seçiminde bulunmamalı.
- Bir önceki grupta olup kaydedilmeyen içerikler `ring2` durumuna geçirilmeli.
- Yeterli `ring0` adayı varken `ring2` içerikler seçilmemeli.
- `ring0` sayısı hedefi dolduramazsa `ring2` ancak yedek aşamada seçilmeli.
- `ring2` adayların `priorityScore` değeri kayıtlı ceza puanını yansıtmalı.
- Profilin depodaki eski halka kayıtları yüklenirken puan bandına göre değil, gösterim geçmişine göre dönüştürülmeli.

Sonuç: Sorun, halka geriletme fonksiyonunun hiç bulunmaması değil. Mevcut kod, eski puan tabanlı halka değerlerini yeni gösterim geçmişi halkalarına çeviriyor; yeni halka sisteminde de ceza puanını her zaman korumuyor. Bu iki sorun, halka seçimindeki yedek doldurma davranışıyla birleşince önceki önerilerin tekrar gelmesine yol açıyor.

Öncelik sırası: önce geçmişe dayalı halka sınıflandırması ve eski kayıtların migrasyonu, sonra `ring2` cezası, en son seçici ve çoklu güncelleme testleri. Testleri çalıştırmadan düzeltmenin tamamlandığını söylemek doğru olmaz; statik incelemeye göre bu üç alanın birlikte düzeltilmesi gerekiyor.
